## 2. 修改前后的具体参数

### 2.1 省界

| 参数 | 修改前 | 修改后 |
| --- | --- | --- |
| 数据来源 | `china-provinces` 全部外环（含国界、海岸线、岛屿，且共享边界重复） | 新文件 `china-province-internal-boundaries.geojson`（仅省际共享边界，去重） |

| 深色底线 | 无 | **无**（见 2.3 说明） |

按缩放的实际线宽（`widthScale = clamp(1 + (zoom − 4.6) × 0.085, 1, 1.34)`）：

| 视图 | 缩放 | 实际线宽 |
| --- | --- | --- |
| 全国 | 2.6–4.6 | 1.30 px |
| 区域 | 6.2 | 约 1.48 px |
| 局地 | 8.0 | 约 1.67 px |
| 近景 | ≥ 10 | 1.74 px |

线宽以 **CSS 像素**计：ribbon 在着色器里按 `u_res`（画布 CSS 尺寸）扩展，设备像素比只影响采样精度，不会让高 DPI 屏出现 2 倍粗细。

### 2.2 国界（未削弱）

国界保持三层：暗色衬底 4.6 px / 0.55 → 金色光晕 8.5 px / 0.20 → 亮金主线 2.7 px / 1.00（`#ffdc9a`），并随缩放同比放大（×1.34，仍远粗于省界）。省界最粗 1.74 px，国界同视口 3.6 px 且带光晕，视觉优先级保持“国界 > 省界 > 其他辅助线”。

### 2.3 为什么省界没有加暗色衬底

设想中的“轻微暗色底线”在实测中失败：省际边界顶点极密（相邻点常只有 0.1–0.5 px），大量半透明四边形沿同一条路径重叠，0.22 透明度的衬底经几十层叠加后变成近黑色宽带，**把 1.3 px 的亮色主线吞掉**，表现为断续黑点。取消衬底后线条恢复连续；在高原浅色地表上依靠 `#d4b177` 与地形的明度差仍可辨认。该结论有截图对比（`screenshots/terrain3d-v22-dev/`，开发期目录不入库）。

## 3. 省界与国界的渲染方法

1. **数据层**：`scripts/build_province_internal_boundaries.py` 用拓扑求出省际边界（见第 4 节）；`scripts/build_national_boundary.py` 求国界并集外轮廓。
2. **贴地**：`DrapedLineLayer` 逐点取**当前渲染网格**的表面高度（`sampleBuildSurface`，双线性插值在三角化用的同一网格上），而不是直接采样更细的 DEM —— 否则线会切入山脊或浮在谷地上方。
3. **屏幕空间 ribbon**：每个线段生成 4 个顶点（起点/终点 × 两侧），在顶点着色器里投影到 CSS 像素空间后再沿法线扩展半个线宽；短于 1.5 px 的线段会被拉伸到 1.5 px，避免亚像素四边形漏掉像素中心。
4. **深度**：线条抬升按“屏幕像素 → 米”换算（约 1.2 px），因此任何缩放与夸张倍数下都与地表保持稳定间隙；细节网格不再使用 polygonOffset（原来 -2/-4 的偏置会把地表推到线条前面），改为在细节片存在时隐藏全国粗网格，从根本上消除重叠面的 z-fighting。
5. **抗锯齿**：片元按到中心线的**像素距离**做 0.55 px 羽化，而不是按 ribbon 宽度比例羽化，保证 1.3 px 的线不会淡成虚影。

## 4. 省际边界去重（是）

`china-province-internal-boundaries.geojson`：

- 方法：34 个省级面各自取边界 → 减去国界并集边界（容差 0.0005°，约 50 m）→ 结果做并集/linemerge → 简化 0.002°（拓扑保持）。
- 结果：**83 条线、18,636 个点、总长约 53,014 km**。
- 去重校验：内部边界落在国界 50 m 缓冲内的长度为 **0.0 km（0.000%）**，说明没有把国界或海岸线重复计入省界；相邻省份的共享边在并集中只保留一次。
- 未做“按距离大面积删线”，唯一的删除是**与国界完全重合**的部分。

## 5. 几何简化与小型岛屿审计

原 `build_national_boundary.py` 会丢弃跨度 < 0.02° 的环。审计（`scripts/audit_boundary_geometry.py`，对未过滤并集计算）显示：

- 原始并集边界共 **517 个环**，原规则会删除 **79 个**；
- 被删的环中包含 **舟山群岛 5 环、南海诸岛 36 环、黄岩岛附近 3 环**；
- 最大被删环跨度 0.0198°（约 2.2 km，周长约 4 km）——属于应当表达的岛礁。

**处理：取消小环过滤，全部 517 个环保留**（15,838 个点，约 380 KB）。性能由 LOD 与抽稀控制，不再删除地理要素。

关键岛屿覆盖（脚本输出）：台湾岛 13 环、海南岛 3 环、崇明岛 2 环、舟山群岛 34 环、南海诸岛 192 环、黄岩岛 4 环。

仍保留 `simplify(0.002°, preserve_topology=True)`（约 200 m），远低于 z6 的 2.2 km 采样间距，不改变国界走向。

> 声明不变：以上只是几何派生，**不构成**国家标准审图；上游审图号 GS(2024)0650 仍只是镜像声明，本应用未单独审图。

## 6. 地名避让

- 实现位置：`HistoricalMap.tsx` 的 `layoutLabels()`，每帧在屏幕空间做贪心布局。
- 顺序：选中的碑刻标记 → 碑刻/原石标记 → 省名 → 次要人物活动地标签。
- 标记圆点**永不隐藏**（地理锚点），只隐藏其文字；文字候选位置依次为原位、右、左、上、下、四角、更远左右，共 13 个候选。
- 尺寸缓存：省名在创建时测量一次；标记文字在创建时测量并缓存在记录里，布局过程不触发重排。
- 缩放策略：全国视图（zoom < 4.6）只显示碑刻级标记文字，人物活动地文字随缩放出现。
- 实测：全国视图 **31/34 个省名可见，重叠 0 组**（测试直接读取 DOM 矩形做矩形相交校验）。

## 7. 真实高程核验修正

原报告写“珠峰 6835 m”。核对过程：

| 检查项 | 结论 |
| --- | --- |
| 参考坐标 | 86.925°E, 27.988°N，为珠峰峰顶常用坐标，未颠倒经纬度 |
| 瓦片定位 | z5 落在 23/13 瓦片，正是喜马拉雅段，瓦片最大值 7188 m |
| Terrarium 解码 | `R×256 + G + B/256 − 32768`，逐瓦片校验尺寸与通道 |
| 分辨率 | z5 像元约 4.4 km，z6 约 2.2 km，峰顶被邻域平均 |
| 是否叠加夸张 | 否。`heightAt()` 返回原始米值，夸张只作用于着色器 |
| 高程基准 | 上游 EGM96 大地水准面（与 WGS84 椭球高相差约数十米，不能解释 2000 m 差距） |

实测：**z5 网格在珠峰位置采样约 6.7–6.8 km，z6 约 8.1 km**；2020 年公布的雪面高程为 **8848.86 m**。因此报告中改为“珠峰所在 z5 网格采样值”，并在 `tests/test_terrain3d.py::test_everest_sample_is_grid_scale_not_summit_height` 中固化“网格采样必须显著低于峰顶高程、且 z6 高于 z5”的关系，防止再被当作真实海拔引用。

## 10. 尚未解决的问题

1. **未单独审图**：仍沿用天地图镜像，上游审图号不是本应用审图证明。
2. **省界在极亮地表上的对比**：取消暗色衬底后，高原大面积浅色区域的省界对比度依赖颜色差；若后续需要更强对比，应改为“按地形亮度自适应描边”，而不是简单加衬底。
3. **抽稀精度**：省际边界按当前 LOD 的顶缩放抽稀到约 1.5 px，深度放大（超过该 LOD 顶缩放）时可能看到轻微折线；尚未实现随缩放动态重采样。
4. **标记遮挡**：DOM 标记仍不参与山体遮挡。
5. **低端 GPU 未实测**：帧率来自单机 RTX 4060。
6. **二维回退样式**：`chinaMapStyle` 的 `province-outline` 已改用去重后的内部边界源，但无 WebGL 时的实际渲染未在浏览器中强制验证（仅代码路径一致）。
